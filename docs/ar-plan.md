# ミニチュアAR機能 メモ

作成日：2026-09-23

## 目的

現地に行かなくても、スポット周辺をスマホで「ミニチュア模型」として見られるようにする。
模型を見て「実物を見に行きたい」と思ってもらい、現地訪問（スタンプラリー）につなげる。

## 方式の比較と決定

| | 1. ミニチュアAR | 2. 3Dビュー | 3. 等身大AR |
|---|---|---|---|
| 見え方 | 机や床の上に模型が現れる（カメラ映像に重ねる） | 画面の中で3D地図を回す | 現地の景色に実物大の3Dが重なる |
| 現地に行く必要 | なし | なし | あり |
| 必要な機器 | スマホ | スマホ・PC | スマホ or ARグラス |
| 難しさ | 中 | 低 | 高（GPS・コンパスの誤差で数m〜数十mずれる） |

**→ 1. ミニチュアAR に決定。**

- 狙いは「行く前に見て、行きたくなってもらう」なので、現地でしか使えない3は合わない。
- ARゴーグルで等身大にするより、ミニチュアの方が全体を把握しやすい。
- 3は将来、現地に来た人向けの体験（例：PLATEAUの浸水想定を実物大で表示）として追加する余地あり。

入口：地図（map.html）の各スポットのポップアップに「ARで見る」ボタンを付ける。

### なぜダムがないのか

1. PLATEAUの「建築物モデル」は屋根と壁があり人が使う建物だけが対象。ダム・橋・砂防堰堤は「土木構造物」で別の種類（橋梁モデル、その他の構造物モデルなど）。それらは自治体が整備した分しかなく、広島県では広島市の橋だけ。
2. PLATEAUは都市計画のためのデータで、市街地が中心。山奥のダム周辺は薄い。

## 今回の方針

- **まずは国土地理院のデータ（標高＋航空写真）だけで作る。** PLATEAUの建物は後で乗せる。
- **1件ずつ作る。最初は魚切ダム（facility-014）。**
- 対象はダム（12件）と宮島口ターミナル周辺を想定。橋は今回はなし（広島市の橋をスポット追加するかは今後検討）。

## データの取得元

| データ | URL | 備考 |
|---|---|---|
| 標高（5m間隔） | `https://cyberjapandata.gsi.go.jp/xyz/dem5a/{z}/{x}/{y}.txt` | 数字の表（1タイル256×256、単位m） |
| 標高（10m間隔） | `https://cyberjapandata.gsi.go.jp/xyz/dem/{z}/{x}/{y}.txt` | 5mがない場所の予備 |
| 航空写真 | `https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg` | JPEG画像 |
| PLATEAUデータ一覧 | `https://api.plateau.reearth.io/datacatalog/plateau-datasets` | 調査で使用 |
| 市町村判定 | `https://mreversegeocoder.gsi.go.jp/` | 国土地理院 逆ジオコーダ |

- 国土地理院のデータは無料で使えるが、**「出典：国土地理院」の表示が必要**。

## 作り方の流れ

```
標高データ（数字の表）──┐
                        ├─→ tools/make_model.py で組み立て ─→ models/facility-XXX.glb ─→ ar.html（model-viewer）で表示・AR
航空写真（JPEG画像）──┘
```

- 標高データ＝地面の「形」、航空写真＝地面の「見た目」。標高がないと平らな板に写真を貼っただけになる。
- 標高データと写真は組み立てに使うだけで保存しない。プロジェクトに残るのは `.glb`（1件数MB程度）だけ。
- 表示には Google の `<model-viewer>` を使う。Android / iPhone ともアプリ不要でAR表示できる。

### 注意点

- 標高データは「地面の高さ」なので、**橋は立体にならない**（写真の絵として見える）。ダムの堤体は地形の段差として出る。
- **スマホでARを使うには https で公開する必要がある**（GitHub Pages を想定）。ローカルの `http://192.168...` ではARは動かない。
